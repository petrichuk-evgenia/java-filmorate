=== ОПИСАНИЕ СТРУКТУРЫ БАЗЫ ДАННЫХ КИНОПОИСКА ===

Цель: Хранение данных о пользователях, фильмах, жанрах, рейтингах, дружбе, отзывах и активности.

ОСНОВНЫЕ СУЩНОСТИ:

1. **mpa_ratings** — рейтинговая категория фильмов по системе MPA.
    - mpa_id: уникальный ID рейтинга.
    - name: название (например, "G", "PG", "R").
    - description: описание рейтинга.

2. **genres** — список жанров фильмов.
    - genre_id: уникальный ID жанра.
    - name: название жанра (например, "Драма", "Комедия").

3. **director** — информация о режиссёрах.
    - director_id: уникальный ID режиссёра.
    - name: имя режиссёра.

4. **users** — пользователи системы.
    - user_id: уникальный ID пользователя.
    - email: уникальный email.
    - login: уникальный логин.
    - name: отображаемое имя (может отличаться от логина).
    - birthday: дата рождения (обязательна).

5. **films** — фильмы.
    - film_id: уникальный ID фильма.
    - name: название фильма.
    - description: краткое описание.
    - release_date: дата выхода.
    - duration: продолжительность в минутах (должна быть > 0).
    - mpa_id: внешний ключ на рейтинг MPA.

6. **film_genres** — связь многие-ко-многим между фильмами и жанрами.
    - film_id, genre_id: составной первичный ключ.
    - ON DELETE CASCADE: при удалении фильма или жанра связь удаляется.

7. **film_director** — связь многие-ко-многим между фильмами и режиссёрами.
    - film_id, director_id: составной первичный ключ.
    - ON DELETE CASCADE.

8. **likes** — лайки фильмов пользователями.
    - film_id, user_id: составной первичный ключ.
    - Пользователь может лайкнуть фильм только один раз.
    - ON DELETE CASCADE: при удалении фильма или пользователя лайк удаляется.

9. **friendships** — дружеские отношения между пользователями (односторонние связи).
    - user_id: инициатор дружбы.
    - friend_id: получатель запроса.
    - status: статус ("CONFIRMED", "PENDING" — не реализовано явно, но можно расширить).
    - Пример: если A добавил B как друга, это отдельная запись от B → A.

10. **events** — лента активности пользователей.
    - event_id: уникальный ID события.
    - user_id: кто совершил действие.
    - timestamp: время события.
    - event_type: тип объекта (например, "FRIEND", "LIKE", "REVIEW").
    - operation: операция ("ADD", "REMOVE", "UPDATE").
    - entity_id: ID сущности, над которой произведено действие.
    - sequence: автоинкрементное поле для упорядочивания (не стандартно, может потребовать корректировки).

11. **reviews** — отзывы пользователей на фильмы.
    - review_id: уникальный ID отзыва.
    - content: текст отзыва.
    - is_positive: положительный ли отзыв.
    - user_id: автор отзыва.
    - film_id: фильм, к которому написан отзыв.
    - useful: подсчитанный рейтинг полезности (обновляется триггером или приложением).
    - created_at: дата создания.

12. **review_feedback** — оценки отзывов другими пользователями (лайки/дизлайки).
    - review_id, user_id: составной первичный ключ.
    - is_like: TRUE — лайк (полезно), FALSE — дизлайк (бесполезно).
    - Один пользователь может оценить каждый отзыв только один раз.

ИНДЕКСЫ:

- Созданы для ускорения поиска по ключевым полям: названия фильмов, email/login пользователей, лайки, дружба, события,
  отзывы.
- Особо важны: idx_reviews_useful DESC — для сортировки самых "полезных" отзывов.
